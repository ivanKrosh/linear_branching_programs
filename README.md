# Лінійні та розгалужені програми — демонстрації

Демонстраційні програми до заняття 8 курсу «Системне програмування»
(ВСП «Фаховий коледж інформаційних систем і технологій КНЕУ ім. Вадима Гетьмана»).

Тема заняття — **як процесор виконує `if` і `switch`, яких у нього немає**: покрокове виконання в налагоджувачі, `CMP` і умовні переходи, знакові й беззнакові порівняння, типові помилки в умовах, таблиця переходів.

## Склад рішення

Рішення `Demo_Lecture_8.slnx`: сім проєктів на C і тека зі сценаріями командного рядка.

| Проєкт | Файл | Що показує |
|---|---|---|
| `Demo1_unsigned` | `unsigned.c` | `-1 < strlen("")` і `DWORD len - 1 < 0` — обидві умови хибні |
| `Demo2_linear` | `linear.c` | лінійна програма: покрокове виконання, один рядок C — кілька машинних команд |
| `Demo3_debugger` | `debugger.c` | `IsDebuggerPresent`: програма поводиться інакше під налагоджувачем; умовна точка зупину |
| `Demo4_branch` | `branch.c` | `if – else` у машинному коді: `CMP` + `JLE`; `JGE` для `int` проти `JAE` для `unsigned`; `if` без переходу в Release |
| `Demo5_pitfalls` | `pitfalls.c` | `if (x = 0)`, `;` після умови, «висячий» `else`, скорочене обчислення `&&` і `\|\|` |
| `Demo6_drive` | `drive.c` | `switch` на результаті `GetDriveTypeA`; прохід крізь `case` без `break` |
| `Demo7_jumptable` | `jumptable.c` | `switch` зі щільними мітками — таблиця переходів, з розрідженими — ланцюжок порівнянь |

| Сценарій | Порядок на занятті | Програма |
|---|---|---|
| `Сценарії/demo01_hook.cmd` | 1 — гачок | `Demo1_unsigned` |
| `Сценарії/demo02_linear.cmd` | 2 | `Demo2_linear` |
| `Сценарії/demo03_nodebugger.cmd` | 3 | `Demo3_debugger` |
| `Сценарії/demo05_pitfalls.cmd` | 4 — частини 5а і 5б | `Demo5_pitfalls` |
| `Сценарії/demo04_if_asm.cmd` | 5 — частини 4а, 4б, 4в | `Demo4_branch` |
| `Сценарії/demo06_drive.cmd` | 6 | `Demo6_drive` |
| `Сценарії/demo07_jumptable.cmd` | 7 | `Demo7_jumptable` |
| `Сценарії/demo01_answer.cmd` | 8 — розв'язка гачка | `Demo1_unsigned` |

Кожен проєкт показується **один раз, від початку до кінця**. `Demo5_pitfalls` іде перед `Demo4_branch` навмисно: спершу умова на рівні мови C (скорочене обчислення, пастки), потім — на рівні процесора (`CMP` і переходи). Номери проєктів лишено незмінними.

Сценарії шукають програми в `x64\Debug\`, потім у `x64\Release\`. Сценарії з машинним кодом (`demo01_answer`, `demo02`, `demo04`, `demo07`) читають лістинги асемблера, які створюються під час збирання, — тому **зберіть рішення в обох конфігураціях**: Debug і Release.

## Як відкрити у Visual Studio

**Що має бути встановлено.** Visual Studio (Community достатньо) з компонентом **«Розробка класичних застосунків на C++»** (Desktop development with C++).

**Крок 1. Відкрити рішення.** Двічі клацнути `Demo_Lecture_8.slnx` або *File → Open → Project/Solution*. У Solution Explorer з'являться сім проєктів і тека **Сценарії**.

> Файл рішення збережено в новому форматі `.slnx`. Якщо ваша версія Visual Studio його не відкриває, оновіть її або відкрийте потрібний `.vcxproj` напряму.

**Крок 2. Зібрати обидві конфігурації.** На панелі зверху вибрати **Debug** і **x64**, *Build → Build Solution* (Ctrl+Shift+B). Потім перемкнути на **Release** і зібрати ще раз.

**Крок 3. Запускати.** На цьому занятті більшість демонстрацій показується **у налагоджувачі**, а не лише сценаріями.

## Покрокове виконання: що робити в налагоджувачі

Конфігурація — **Debug**. F5 запускає **стартовий проєкт** (у Solution Explorer він жирний), а не той, у якому відкрито файл. Зручніше один раз налаштувати: правою кнопкою на рішенні → *Properties* → *Startup Project* → **Current selection**. Тоді F5 запускає проєкт, виділений у Solution Explorer. Інакше — правою кнопкою на проєкті → **Set as Startup Project**.

| Клавіша | Дія |
|---|---|
| `F9` | поставити або зняти точку зупину на рядку |
| `F5` | запустити під налагоджувачем / продовжити до наступної точки зупину |
| `Ctrl+F5` | запустити **без** налагоджувача |
| `F10` | виконати рядок (виклик функції — одним кроком) |
| `F11` | виконати рядок, увійшовши у функцію |
| `Shift+F11` | вийти з функції |
| `Ctrl+Alt+D` | вікно **Disassembly** (під час налагодження) |
| `Ctrl+Alt+G` | вікно **Registers**; правою кнопкою → *Flags* — прапорці `ZR`, `PL`, `CY`, `OV` |

**`Demo2_linear`.** F9 на рядку `int total = 10000;`, F5, далі F10. Стежте у вікні **Autos**, як змінні отримують значення. Потім Ctrl+Shift+F5 (перезапуск), F10 і *Ctrl+Alt+D*: під кожним рядком C — його машинні команди. F10 у вікні Disassembly виконує **одну команду**.

**`Demo3_debugger`.** Спершу Ctrl+F5 (або `demo03_nodebugger.cmd`), потім F5 з точкою зупину на `return 0` — перший рядок виводу зміниться. Умовна точка зупину: F9 на рядку `sum += i * i;`, правою кнопкою на червоній точці → **Conditions** → `i == 7`. Після зупинки подивіться `i` і `sum` у вікні **Locals**. **Set Next Statement** (Ctrl+Shift+F10): F9 на рядку 9 `if (IsDebuggerPresent())`, F5, перетягніть жовту стрілку на рядок 12 — під налагоджувачем надрукується `No debugger`.

**`Demo4_branch`.** F9 на рядку `if (x > 10)` у `classify`, F5, *Ctrl+Alt+D*. Відкрийте **Registers** з прапорцями й виконайте `cmp` через F10 — видно, як змінюються прапорці перед `jle`, і куди переходить стрілка.

**Аргументи командного рядка.** У `Demo6_drive` уже задано `C:` — без аргументу програма лише друкує підказку. `Demo4_branch` без аргументу бере `x = 5` (перехід `jle` виконується), `Demo7_jumptable` — `3`. Змінити, наприклад на `42` чи `C: nobreak`: правою кнопкою на проєкті → *Properties* → **Configuration Properties → Debugging → Command Arguments**.

## Налаштування проєктів

Проєкти створено зі стандартного шаблону консольної програми з кількома змінами. **Не повертайте їх**, інакше вікно Disassembly не збігатиметься з тим, що показано на занятті:

| Параметр (*Properties → C/C++*) | Значення | Навіщо |
|---|---|---|
| *General → Warning Level* | `/W4` | щоб побачити попередження `C4706` у `Demo5_pitfalls` |
| *General → Support Just My Code Debugging* | No (Debug) | без цього на початку кожної функції з'являється зайвий виклик |
| *Code Generation → Basic Runtime Checks* | Default (Debug) | без цього в машинному коді з'являються додаткові перевірки стека |
| *General → Debug Information Format* | `/Zi` (Debug) | звичайний `.pdb` замість режиму Edit and Continue |
| *Output Files → Assembler Output* | `/FA` | лістинг асемблера `x64\Debug\*.asm` у теці проєкту — його читають сценарії |
| *Optimization → Whole Program Optimization* | No (Release) | інакше компілятор не створює лістинг: код генерується лише під час компонування |
| *Command Line → Additional Options* | `/utf-8` | вихідні файли збережено в UTF-8 |

## Як зібрати з командного рядка

**Developer Command Prompt for VS**, з кореня репозиторію:

```
msbuild Demo_Lecture_8.slnx /p:Configuration=Debug /p:Platform=x64
msbuild Demo_Lecture_8.slnx /p:Configuration=Release /p:Platform=x64
```

Лістинг асемблера для окремого файлу:

```
cl /nologo /Od /FA /c Demo4_branch\branch.c      -> branch.asm, без оптимізації
cl /nologo /O2 /FA /c Demo4_branch\branch.c      -> branch.asm, з оптимізацією
```

## Відомі граблі

**Сценарій пише «listing not found».** Не зібрано відповідну конфігурацію. `demo04_if_asm.cmd` і `demo07_jumptable.cmd` потребують і Debug, і Release.

**У вікні Disassembly інший код, ніж на слайдах.** Перевірте конфігурацію (Debug) і налаштування з таблиці вище. У Release налагоджувач «перестрибує» рядки, а змінні показуються як *optimized away* — це нормально.

**Попередження `C4706` у `Demo5_pitfalls`.** Воно навмисне: це і є помилка номер 1. Рішення збирається успішно.

**Консоль закривається одразу після F5.** Поставте точку зупину на `return 0` або вимкніть *Tools → Options → Debugging → General → Automatically close the console when debugging stops*.

**Кодування сценаріїв.** Файли `.cmd` збережено в **UTF-8 з CRLF**, перший рядок після `@echo off` — `chcp 65001 > nul`. `show_asm.ps1` навмисно містить лише латиницю: Windows PowerShell 5.1 читає файл без BOM у кодовій сторінці ANSI.
